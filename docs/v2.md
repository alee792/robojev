# v2: Planner, Sequencer, Spotter, Listener

v1 showed that Jev can sit inside a real-arm control loop (138 ms median, event-driven, no errors)
and that it is good at grounding words to objects and places. It did not show that Jev beats a
script as a policy: we gave it a scriptable task, wrote the script into its prompt, and never ran the
comparison (`docs/assessment.md`). v2 splits the work so that each part does only what it is good at.

## Principles

- **Jev decides meaning; code decides motion.** Jev never emits a number. Code owns geometry,
  arithmetic, limits and feasibility, and offers Jev only options it has already checked.
- **A slow model is never on the critical path.** The arm always has something sensible to do from
  the fast layers. The Planner customises and amends; it does not gate motion.
- **Only ask Jev what code cannot answer.** Each question has an ablation that shows what gets worse
  without it.
- **Decision rate follows the world.** Requests are change-driven, not clocked.
- **Constraints are enforced by code and switched on by Jev.** They are typed relations bound to
  entity IDs and re-evaluated every control cycle against live tracks.
- **Safety does not depend on any model.** Confidence gates which option to act on; it is not a
  safety mechanism. A layer can only make the arm more cautious than the code rules, never less.
- **Nothing object-specific in prompts.** Task-specific wording is written at run time by the
  Planner, from the user's words, into templates.
- **Every claim has a baseline and a distribution.**

## Layers

| Layer | Who | When | Job |
|---|---|---|---|
| Perception | VLM + depth/segmentation/tracking | VLM once per new object; tracking at frame rate | Scene: named, tracked entities |
| **Planner** | LLM (Haiku-class first, larger on escalation) | On a new task or an escalation | Compile the task into a Plan |
| **Sequencer** | Jev | Skill finished or failed, chunk boundary, scene change | Next skill, branch, done, escalate |
| **Spotter** | Jev | Something moves or appears near the arm | Continue / slow / hold / back off / evade; which conditional orders are active |
| **Listener** | Jev | Only when the user types | Classify intent; pick knob values; when to apply |
| Skills | Code: scripts, VLA policies, VLM checks | Their own rates | Execute; report running / done / failed(reason) |
| Limiter | Code | Every command | Clip every setpoint and chunk to active constraints and safety limits |
| Arbiter | Code | Every tick | Spotter beats Sequencer; STOP beats everything |

Jev is also the **router**. Every Jev decision can end in one of three places: act on the pick
(high confidence), hand off to a VLM check or a small model (middle), or escalate to the Planner
(low confidence, `ask_a_smarter_model`, or a `new_task` intent).

## Vocabulary

| Term | Meaning | Produced by |
|---|---|---|
| Scene | Entities present: id, name, position, attributes | Perception |
| Status | What the arm is doing: holding, current skill, last result | Code |
| Task | The active instruction, as compiled | Planner |
| Orders | Standing constraints ("don't touch the green one") | User, via Planner, into code and Jev |
| Plan | Bindings + skill graph + knobs + question templates | Planner |
| Knobs | The Plan's declared adjustable settings, each with enumerated values | Planner |
| Facts | Relations code computes, including the answer under each knob value | Code |
| Utterance | New text from the user | User |
| State | The JSON sent to Jev: the above, filtered for one layer | Code |
| Questions | Typed choices put to one layer | Plan templates |
| Pick | Jev's answer and its confidence | Jev |
| Intent | The Listener's classification of an utterance, and nothing else | Listener |

## Skills

Every skill has the same contract, whatever implements it:

```
precondition(world) -> bool         # the Sequencer only sees skills whose preconditions hold
start(args)                         # entity IDs, and for a VLA the instruction text, bound by the Planner
step() -> chunk                     # ~0.5-1 s of setpoints; the Limiter clips each chunk
interruptible at chunk boundaries   # where the Sequencer and Spotter decide
status() -> running | done | failed(reason)
success check                       # code, or a VLM check
```

| Kind | Examples | Why |
|---|---|---|
| Scripted | move above, carry, place, retreat, survey, block grasp | Coarse, geometric, predictable |
| VLA policy (emits action chunks) | "pick up the scissors by the handles" | Dexterous, contact-rich, not scriptable |
| VLM check | "is the grasp secure?" | A question text cannot answer |

Which kind a step uses is a per-object choice the Planner makes. Switching during a run (the
scripted grasp failed twice, fall back to the VLA) is the Sequencer's.

## Constraints

| Type | Example order | What code enforces |
|---|---|---|
| Spatial | "stay away from the laptop" | Keep-out / keep-in / not-above, attached to a track |
| Kinematic | "go slow near the baby", "gently" | Speed / acceleration / force caps |
| Orientation | "keep it upright" | Tilt limit while holding |
| Contact | "don't touch the white one" | Excluded from targets, and a contact check |
| Temporal | "wait until I let go" | Hold until a condition holds |
| Conditional | "if someone reaches in, stop" | Any of the above, only while a condition holds |

Code enforces the constraint; Jev decides when it applies, where that needs judgment ("is that
someone reaching in?"). A VLA's output passes through the same Limiter.

## The Listener, worked through

Blocks 1-6 are to be lined up in a tray, ascending. The Planner declares knobs `order`
(ascending | descending), `placement` (left-to-right | right-to-left) and `pace` (normal | slow).
Code computes the next block under each knob value. Blocks 1 and 2 are placed; the arm is carrying 3.
The user types "actually, reverse it".

| t | What happens |
|---|---|
| 0 ms | Utterance arrives; the Listener's request goes out |
| ~150 ms | `intent = adjust`, `order = descending`, `when = after this block` |
| ~150 ms | Code sets the knob; the next block is now 6. The Sequencer decides what to do with block 3 |
| 0-3 s, in parallel | The Planner reviews what "reverse" means for blocks already in the tray, and amends the Plan or asks the user |

An utterance no knob covers is `new_task` (or `adjust` with everything `unchanged`): the arm
finishes to a safe point and holds while the Planner recompiles. A missing knob costs seconds, not a
wrong action. STOP never depends on a model: the dashboard button, and a plain keyword match, act in
code.

## Crawl, walk, run

| Stage | Task | Shows | Pass |
|---|---|---|---|
| Crawl | Sort blocks into bins or a tray, static scene, several sorting rules | The pipeline end to end; different rules with no code change | N blocks sorted correctly over K trials, per rule |
| Walk | A person interferes: moves the target, un-sorts a block, reaches into the path, holds a block out, moves a forbidden block into the way | Sequencer re-targets; Spotter activates constraints and evades | Latency, unaided recovery rate, zero hand contact, task completes; compared against no-Spotter |
| Run | VLA skills for a dexterous object; handover; mid-task language through the Listener | Skills that cannot be scripted; live language | To be set |

Crawl and walk use scripted skills only; the skill contract is built for VLAs from the start.
Build against a MuJoCo blocks-and-bins scene first, and accept on the real arm. The first hardware
dependency is an overhead camera with an AprilTag calibration. When walk puts a hand near the
moving arm, a code rule caps speed or stops on a detected hand within a set distance, regardless
of Jev.

**Kept from v1**: loop plumbing, the Jev client, the change detector, arm drivers, the safety layer,
the dashboard. **Replaced**: the question batteries, the brain, depth-only perception, the
cup-specific skills.

## Spikes

- **E11** (`experiments/e11_reorder.py`): one decision after "reverse it". Can Jev do the
  reordering itself (`raw`) or only map the utterance onto code's per-knob answer (`solved`)? Does
  confidence route its mistakes? A unit test of one capability boundary.
- **E12** (`experiments/e12_blocksworld.py`): a text-only blocks world, closed loop, with the
  Sequencer, Spotter and Listener as specified here, a scripted human, and ablations (no Spotter, no
  Listener, raw vs solved facts). Scores outcomes: completion, recoveries, escalations, time from an
  utterance to changed behaviour, violations.

Both run from a machine with a TypeSafe key; see `context/07-experiments-to-run.md`.

## Open decisions

- Plan format: a schema-checked skill graph (current choice) or generated code.
- How many knobs a Plan declares (2-5 is the guess; measure how often utterances fall through).
- While the Planner reviews a Listener change: continue on high confidence, pause on middling.
- Which LLM and VLM, and the escalation latency budget.
